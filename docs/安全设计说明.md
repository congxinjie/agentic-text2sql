# 安全设计说明

> 关联:COMPETITION.md §8 数据合规红线;评审维度"安全合规 10 分"。

## 1. 数据合规

- 数据集来源:比赛主办方提供的券商客户营销数据集(见 docs/数据说明.md)。
- 疑似个人字段:客户姓名 `name` 已脱敏;`sor_pty_id`(经纪客户号)在演示/报告/截图/视频中一律不出现;演示输出客户明细聚合到看不出个体。
- 禁止联网抓取未授权数据、禁止引入外部真实个人信息。
- 全部结论可复现:评测命令见 README 与 docs/评测报告-基线.md。

## 2. 只读三保险(引擎既有,不动)

| 层级 | 措施 |
|---|---|
| 连接层 | `sqlite3.connect(f"file:{db}?mode=ro", uri=True)` 文件级只读 |
| 语句层 | `PRAGMA query_only=ON` SQLite 拒绝一切写操作 |
| 校验层 | 只放行单条 SELECT/WITH/EXPLAIN;剥离注释;多语句拒绝;`WITH` 解析主语句动词,拒绝 `WITH ... DELETE/UPDATE/INSERT/REPLACE/VALUES 非只读` |

## 3. 防幻觉围栏(表/指标/SQL/结果合法性)

- 检索阶段:候选表/列与库元数据逐字校验,不存在的直接剔除并记录。
- 计划检查阶段(程序化):计划引用表必须存在;"表.列"引用必须真实;指标/维度/时间范围必须覆盖;有指标必须有聚合。
- SQL 校验阶段:见 §2。
- 评测判定器:表/列幻觉率结构化比对,基线恒为 0%(见评测报告)。
- 结果合法性检查(阶段 8):空结果、截断、单行分别给出提示,结论注明默认假设与数据局限。

## 4. 越界问题处理

- 库外概念/闲聊/主观建议(如"今天天气怎么样?适合买基金吗?")→ 理解阶段 answerable=false,拒绝并给原因,不生成 SQL。
- 库中无引用表的码(300 证件/400 风险等级)→ 按不可答处理(口径红线,见评测口径定义 §3.4)。

## 5. 密钥与配置

- LLM 密钥在 `text2sql_demo/.env.local`(已被 .gitignore 排除),不打印、不入库、不进报告。
- 环境变量 `LLM_API_KEY` 亦可;支持 `LLM_BASE_URL`/`LLM_MODEL` 覆盖(私有化模型适配,不改代码)。
- UI 运行仅本地只读库;演示模式无需外部账号。

## 6. LLM 故障兜底

- 超时/连接/429/5xx:调用层指数退避重试 ≤3 次(R9);仍失败→阶段 FAIL 记录 + 友好错误卡片。
- JSON 输出空/截断:重试 1 次并提示精简;仍失败→阶段 FAIL,不崩溃。
- 全程 Trace 留痕,异常路径可审计。
