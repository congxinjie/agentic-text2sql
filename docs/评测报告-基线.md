## 5. 规则变更记录(R1-R10 冻结 + M6 机制)

- R1-R10:见 docs/评测口径定义.md §8(judge 冻结,本轮未改判定器)。
- M6-1 计划阶段结构化声明:`output_columns`/`dimension_labels` 进计划 JSON;`_check_plan` 校验缺失/字段不实/标量多列/排名误加客户数/口径断言。
- M6-2 生成阶段硬约束:`_generate_sql` 把声明列写入硬约束,缺失即带反馈重写一次;禁止中间列、CROSS JOIN,跨表合计 LEFT JOIN+COALESCE。
- M6-3 结果阶段程序化校验:`_check_result` 校验声明列都在结果表头,缺失复用 `_repair_sql` 修复一次。
- M6-4 口径断言(可配置):`caliber_assertions` 由 harness 注入(持有→份额、交易额=buy_amt+sell_amt、科创 LIKE、盈亏口径),计划不满足即拒绝并重规划一次。
- M6-5 工具:`benchmark/run_eval.py --ids/--limit`(默认全量行为不变;部分运行只落 run JSON,不覆盖本报告)。
